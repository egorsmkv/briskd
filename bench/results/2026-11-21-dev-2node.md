# ircd bench

Measured 2026-11-21 14:40:38 UTC against `127.0.0.1:6667`.
Welcome numeric: `:irc.dev 001 b28510267 :Welcome to IRC b28510267!b28510267@172.20.0.1`.
Load generator event loop: `asyncio`.

This is the development server (`rebar3 shell` in the OTP 29 container),
not a packaged release. One container sample taken during registration:
`irc-server_ircd-dev_1 cpu=1.04% mem=294.3MiB / 31.26GiB`. OTP: `29 17.1.1`.

Two linked development servers (`docker-compose.dev.yml`): `irc.dev` on
6667 and `irc2.dev` on 6668. High-load clients alternate between them, so
every channel spans the link. Both servers were switched from the configured
`trace` log level to `info` at runtime for this run: at `trace` every command
is a synchronous write to the container terminal, which throttles the server
and, through the log handler's burst limit, drops warnings. Container samples
cover `irc-server_ircd-dev_1` only. The traffic matrix below runs against
`irc.dev` alone.

## Traffic

- Sequential `PING`/`PONG`, 100 samples, 0 errors.
  p50 0.32 ms, p95 0.37 ms, p99 0.41 ms.
- Pipelined `PING`, 401 of 1000 `PONG` replies in 0.035s (11398.6/s).
- Registration, 200 welcomes of 200 attempts, concurrency 32, 0.397s (504.0/s). Welcome p50 63.30 ms, p95 67.38 ms. Errors: 0.
- Channel `PRIVMSG`: 8 members, 800 messages sent, 5600 of 5600 deliveries in 0.105s (53106.5/s deliveries).

A sender does not receive its own channel message, so the expected
delivery count is `members * messages_each * (members - 1)`.
Clients quit at the end of each phase. Nicks stay reserved for 60 seconds.

## High load

10000 of 10000 clients connected and registered in 32.6 s (306.7/s); welcome p50 435.55 ms, p99 5153.86 ms.
Clients per server (round-robin, so channels span the servers and every message crosses the link): `127.0.0.1:6667` 5000, `127.0.0.1:6668` 5000.
Every server listed every channel member 0.44 s after the joins (the send phase waits for this).

100,000 channel messages from 10,000 clients in 200 channels of up to 50, sent as one burst per client in 0.63 s.
Deliveries: 4,900,000 of 4,900,000 expected in 52.51 s, 93324.4/s.
Delivery latency from send to receipt (49,000 sampled messages): p50 30694.23 ms, p95 50139.25 ms, p99 51727.84 ms, p99.9 52022.44 ms, max 52054.07 ms.
Disconnects during the phase: 0; error numerics: none.
After the phase a new client registered within 20.9 s.
Load generator CPU during the phase: 90% of one core .
