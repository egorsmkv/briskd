Measured 2026-11-21 11:53:04 UTC against `127.0.0.1:16667`.
Welcome numeric: `:irc.example.org 001 b25281751 :Welcome to IRC b25281751!b25281751@172.17.0.1`.
Load generator event loop: `rsloop`.

This is the production image (`Dockerfile.prod`: the release with
ERTS included, on Debian slim) run as `docker-compose.prod.yml` runs it:
`config/ircd.prod.json` (flood limits, DroneBL, `channels` retention,
JSON info logging) with only `max_clients` raised so the high-load
clients fit, `ulimit -n` 65536, `init`, and a fresh data volume, on
another host port (`bench/prod`).

One container sample taken during registration: `ircd-prod-bench cpu=0.80% mem=139.1MiB / 31.26GiB`.
OTP/ERTS: `ERTS 17.1.1, release 0.1.0`.
Warmed up with 50 registrations before the measured phases.

`PING <marker>`; latency is the time until that PONG, so it covers the whole
reply. Errors count 4xx/5xx numerics, `FAIL` replies, and timeouts.
The client is paced to at most 40 lines per second (below
the server's flood limit); the pause is outside the measured latency, so
ops/s reflects the pacing, not the server's capacity.
